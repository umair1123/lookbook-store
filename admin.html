Setup & Backup

One-time Supabase setup

  1. Go to supabase.com/dashboard, sign up (no card needed), and create a new project. Pick any name and a database password (save it somewhere — you likely won't need it again, but it's your project's master password).
  2. In the left sidebar, click the SQL Editor icon → New query. Paste in the schema below and click Run. This creates your tables and locks them down so only you can edit them.
  3. In the left sidebar, click Authentication → Users → Add user. Enter the email and password you'll use to log into this Store Manager, and set "Auto Confirm User" to on. This is your real admin login.
  4. Still in Authentication, click Providers → Email and turn off "Allow new users to sign up" — this stops anyone else from creating their own account.
  5. Click the gear icon (bottom left) → Project Settings → API. Copy the Project URL and the anon public key (not the service_role key).
  6. Open supabase-config.js (in the same folder as this file) and paste those two values in, replacing the YOUR_… placeholders.
  7. Upload index.html, admin.html, and supabase-config.js to your GitHub repo (overwrite the old versions), commit, then reload this page and sign in.

Database schema & security rules (paste into SQL Editor)

This creates your three tables, turns on Row Level Security, and adds policies so anyone can read your catalog (so your site works) but only your signed-in admin account can change anything. It also switches on realtime sync.

create table products ( id uuid primary key default gen_random_uuid(), name text not null, cat text not null, sub text, price numeric not null, was numeric, img text, tag text, rating int default 4, sizes text[] default '{}', sizes_stock jsonb not null default '[]', added bigint default (extract(epoch from now()) * 1000) ); create table deals ( key text primary key, enabled boolean default true, title text, kicker text, description text, countdown_hours int, countdown_minutes int ); create table coupons ( code text not null primary key, type text not null, value numeric default 0, label text, min numeric, enabled boolean default true ); alter table products enable row level security; alter table deals enable row level security; alter table coupons enable row level security; create policy "Public read products" on products for select using (true); create policy "Public read deals" on deals for select using (true); create policy "Public read coupons" on coupons for select using (true); create policy "Admins write products" on products for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); create policy "Admins write deals" on deals for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); create policy "Admins write coupons" on coupons for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); alter publication supabase_realtime add table products; alter publication supabase_realtime add table deals; alter publication supabase_realtime add table coupons; create table subcategories ( cat text not null, name text not null, primary key (cat, name) ); alter table subcategories enable row level security; create policy "Public read subcategories" on subcategories for select using (true); create policy "Admins write subcategories" on subcategories for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); alter publication supabase_realtime add table subcategories; create table categories ( key text primary key, label text not null, size_type text not null default 'apparel', sort_order int default 0, separate_page boolean not null default false ); alter table categories enable row level security; create policy "Public read categories" on categories for select using (true); create policy "Admins write categories" on categories for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); alter publication supabase_realtime add table categories;

Already set up? Add the new Subcategories table

If you ran the schema above before Subcategories existed, just run this smaller addition once in the SQL Editor — it won't affect your existing products, deals, or coupons.

create table subcategories ( cat text not null, name text not null, primary key (cat, name) ); alter table subcategories enable row level security; create policy "Public read subcategories" on subcategories for select using (true); create policy "Admins write subcategories" on subcategories for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); alter publication supabase_realtime add table subcategories;

Also new: add the Categories table

Run this once too — it lets you manage top-level categories (Women, Men, etc.) from the Categories tab instead of them being fixed in the code. Existing products keep working with their current category either way.

create table categories ( key text primary key, label text not null, size_type text not null default 'apparel', sort_order int default 0, separate_page boolean not null default false ); alter table categories enable row level security; create policy "Public read categories" on categories for select using (true); create policy "Admins write categories" on categories for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); alter publication supabase_realtime add table categories;

Already created the categories table before "separate page" existed? Run just this instead:

alter table categories add column if not exists separate_page boolean not null default false;

Also new: inventory / stock tracking

Run this once to add per-size stock counts to your products table. Existing products keep working — they'll just show as untracked (always in stock) until you set real numbers for them in the Products tab.

alter table products add column if not exists sizes_stock jsonb not null default '[]';

Also new: Cash on Delivery orders

Run this once to enable real order placement. It creates an orders table (shoppers can only create orders, never read anyone else's — only your signed-in account can view or manage them), and allows shoppers' browsers to update just the stock count on products when an order is placed, without giving them access to change prices, names, or anything else.

create table orders ( id uuid primary key default gen_random_uuid(), customer_name text not null, customer_email text, customer_phone text not null, customer_country text, customer_province text, customer_city text, customer_address text not null, items jsonb not null, subtotal numeric not null, discount numeric not null default 0, coupon_code text, total numeric not null, status text not null default 'pending', created_at timestamptz not null default now() ); alter table orders enable row level security; create policy "Anyone can place an order" on orders for insert with check (true); create policy "Admins read orders" on orders for select using (auth.role() = 'authenticated'); create policy "Admins update orders" on orders for update using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); create policy "Admins delete orders" on orders for delete using (auth.role() = 'authenticated'); alter publication supabase_realtime add table orders; create policy "Public can adjust stock when ordering" on products for update using (true) with check (true); grant update (sizes_stock) on products to anon;

Already created the orders table before email/location fields existed? Run just this instead:

alter table orders add column if not exists customer_email text; alter table orders add column if not exists customer_country text; alter table orders add column if not exists customer_province text; alter table orders add column if not exists customer_city text;

Also new: shipping cost & free-shipping threshold

Run this once to enable a shipping fee at checkout, with an optional "free shipping over Rs. X" offer you control from the Deals & Discounts tab.

create table shipping_settings ( id int primary key default 1, enabled boolean not null default true, flat_rate numeric not null default 0, free_threshold numeric ); alter table shipping_settings enable row level security; create policy "Public read shipping" on shipping_settings for select using (true); create policy "Admins write shipping" on shipping_settings for all using (auth.role() = 'authenticated') with check (auth.role() = 'authenticated'); alter publication supabase_realtime add table shipping_settings; insert into shipping_settings (id, enabled, flat_rate, free_threshold) values (1, true, 200, 2000) on conflict (id) do nothing; alter table orders add column if not exists shipping_cost numeric not null default 0;
